# ChatVerse Interface System

## Intent

### Human

ChatVerse 同时服务两类紧密相连的人：

- 参与者：打开一个群，阅读消息、插话、观察角色关系，希望它首先像一款可信的群聊软件。
- 创作者：配置角色、世界、场景、关系和运行方式，希望它像一套清晰、可回退的群组创作工具。

参与者通常从群列表进入聊天；创作者通常从某个群进入工作台，再回到聊天验证结果。两种身份可以由同一个人随时切换。

### Core task

围绕一个群完成连续闭环：

1. 找到或创建群。
2. 理解群里是谁、当前发生什么。
3. 进入聊天并自然参与。
4. 必要时进入后台修改群设定。
5. 回到聊天观察改变。
6. 导出群包进行分享。

### Feel

前台聊天应当有真实社交软件的熟悉感、温度和节奏；后台工作台应当安静、精确、可扫描。整体不是二次元主题站，也不是通用 SaaS 后台，而是一套“正在运转的角色群组”产品。

## Domain Exploration

### Domain

- 群、成员、在线状态和未读
- 对话、短消息串、贴纸和提及
- 角色、关系、立场和记忆
- 世界、场景、事件和时间推进
- 前台、后台、导演和 Harness
- 群包、模板、安装和分享
- 运行、等待、生成和提交

### Color world

- 聊天纸白：消息阅读区域和编辑画布
- 墨黑：正文、主要命令和群身份
- 雾灰：导航、分隔和次级信息
- 信号青绿：运行、连接、可进入状态
- 提醒琥珀：等待、未保存和需要检查
- 中止朱红：停止、删除和运行错误
- 角色身份色：仅属于头像、关系节点和角色标识，不成为页面装饰色

### Signature

“前台 / 后台轨道”是 ChatVerse 的结构签名。

- 前台轨道承载群聊、成员与当前场景，只展示参与对话所需的信息。
- 后台轨道承载角色、世界、场景、关系、运行和调试。
- 用户始终知道自己正在“群里”还是“编辑这个群”，切换时群头像、群名和运行状态保持连续。
- 运行状态使用一条克制的状态轨道表达：等待、生成、已排程、已发送，而不是堆叠调试卡片。

这个签名至少出现在：全局导航、群工作区导航、聊天头部、运行观察条和移动端群菜单。

### Rejected defaults

- 拒绝“大标题 + 模板卡片 + 数据卡片”的落地页首页；群库应像真实会话列表，最近活动和继续聊天优先。
- 拒绝所有功能塞进聊天页左右抽屉；群设置、角色和关系是独立任务，应拥有独立路由和编辑空间。
- 拒绝用渐变头像、渐变背景和大量彩色卡片制造活泼；角色资源与消息内容本身承担个性。
- 拒绝把 Core 术语直接暴露给普通参与者；运行与调试信息进入后台轨道。
- 拒绝所有区域使用相同白卡；页面区带、列表、检查器和画布应有不同但一致的结构表达。

## Direction

方向名称：**Living Ensemble / 运转中的群像**

聊天前台接近成熟社交软件：消息占据视觉中心，群信息保持克制，角色身份清楚但不喧闹。创作后台接近编辑器：固定群级导航、中央画布、按需出现的检查器，支持高密度连续操作。

## Depth Strategy

采用 **surface shifts + quiet borders**：

- 不使用装饰性大阴影。
- 页面层级主要依靠背景明度变化和低对比边框。
- 浮层、菜单和对话框允许一层轻阴影，用于说明悬浮关系。
- 输入区域略深于父级表面，表达“可写入”。
- 侧栏与主画布保持同一颜色世界，不制造割裂的侧栏主题。

## Tokens

### Color primitives

```css
--canvas: #f4f5f2;
--surface: #ffffff;
--surface-subtle: #eef0ed;
--surface-inset: #e8ebe7;
--ink: #171a18;
--ink-secondary: #4f5752;
--ink-tertiary: #737c76;
--ink-muted: #9aa19c;
--line: rgba(23, 26, 24, 0.10);
--line-strong: rgba(23, 26, 24, 0.18);
--signal: #087f6a;
--signal-soft: #dcefe9;
--warning: #a86514;
--warning-soft: #f6ead6;
--danger: #bd3d46;
--danger-soft: #f7e2e4;
--focus: #168b76;
```

角色身份色属于内容数据，必须满足文本或图形对比度；不能替代产品的 `--signal`。

### Text hierarchy

- Primary：`--ink`，页面标题、消息正文、核心值。
- Secondary：`--ink-secondary`，说明和列表摘要。
- Tertiary：`--ink-tertiary`，时间、计数、辅助标签。
- Muted：`--ink-muted`，禁用、占位和低优先级元数据。

### Typography

- 中文产品字体：`"Noto Sans SC", "Microsoft YaHei", sans-serif`。
- 数字、时间和调试字段：`"IBM Plex Mono", "SFMono-Regular", monospace`。
- 不依赖负字距制造精致感，`letter-spacing: 0`。
- 使用约 1.2 的紧凑比例：
  - Caption：12/18，400 或 500
  - Body：14/22，400
  - Emphasis：14/22，600
  - Section：17/24，600
  - Page：22/30，650
  - Product：28/36，650，仅用于群库空状态或首次创建

### Spacing

基础单位为 4px：

- Micro：4、8
- Control：8、12
- Component：12、16
- Section：20、24
- Major：32、40

聊天消息区域使用 12px 紧凑密度；表单编辑区使用 16px 标准密度；首次创建和空状态允许 24px。

### Radius

- 小型控制：4px
- 按钮、输入、列表选中态：6px
- 面板、浮层、消息气泡：8px
- 对话框：8px
- 头像：群头像 8px，人物头像 50%

不使用药丸形容器承载普通文字。药丸仅用于状态、计数和筛选 token。

### Borders and focus

- 默认边框：1px `--line`
- 强调边框：1px `--line-strong`
- 焦点：2px `--focus`，外偏移 2px
- 分区优先使用留白和背景变化，边框只在结构需要时出现

## Layout System

### Global shell

- 桌面全局导航：64px，仅承担群库、最近聊天、创作、应用设置。
- 群工作区导航：216px，可折叠至 64px；显示群身份及群内页面。
- 主内容：`minmax(0, 1fr)`。
- 检查器：320px，仅在选择对象或查看运行细节时出现。
- 最大阅读宽度只用于消息正文和文档，不限制关系画布、列表和编辑器。

### Breakpoints

- `>= 1280px`：全局导航 + 群导航 + 主内容，可选检查器。
- `768–1279px`：全局导航收窄，群导航按页面折叠；检查器为覆盖层。
- `< 768px`：底部主导航；聊天单栏；群后台使用页面级返回与分段导航。
- `< 420px`：控制区允许换行，图标命令保留 40px 最小触控尺寸。

## Navigation Patterns

### Global navigation

- 群聊
- 创作
- 最近
- 应用设置

不提供“仪表盘”入口。首页就是群库。

### Group workspace navigation

- 聊天
- 概览
- 角色
- 用户角色
- 世界书
- 场景
- 关系
- 运行
- 资源
- 群设置

聊天属于前台轨道；其余页面属于后台轨道。调试位于“运行”页面内，不进入全局导航。

## Reusable Patterns

### Primary button

- 36px 高，12px 横向内边距，6px 圆角
- `--ink` 背景、白色文本
- 一个页面最多一个主要动作

### Quiet button

- 36px 高，透明背景，6px 圆角
- hover 使用 `--surface-subtle`
- 图标命令优先只显示图标并提供 tooltip

### Field

- 36px 最小高度，12px 横向内边距，6px 圆角
- `--surface-inset` 背景，默认无强边框
- 标签在字段上方，帮助与错误文本占据固定信息层级

### Collection row

- 56–72px 高，根据摘要长度变化
- 左侧身份，中间名称和摘要，右侧时间或状态
- 整行可进入详情；次级菜单不抢占主点击区域
- 群库、角色列表、场景列表和资源列表共享结构

### Inspector

- 320px 宽，按选择对象出现
- 顶部显示对象身份，正文按可折叠区组织
- 不把检查器嵌套成多层卡片

### Runtime rail

- 横向或纵向时间轨道
- 状态点：等待、生成、排程、提交、错误
- 普通用户只看状态摘要；开发模式可展开原始事件
- 不用不断刷新的相同“等待 idle”列表作为主展示

### Message cluster

- 同一角色连续消息组成一簇，只在首条显示头像与姓名
- 短句保持独立气泡；大贴纸独立气泡；小表情可随文本
- 时间作为簇级元数据，不重复占据每条消息
- 自己的消息和角色消息通过对齐与表面区分，不依赖高饱和蓝色

## Motion

- 页面切换：120–160ms 淡入，不做整页滑动。
- 检查器与移动抽屉：180ms。
- 新消息：120ms opacity + 4px 位移。
- 运行状态变化：颜色和位置在 160ms 内过渡。
- 尊重 `prefers-reduced-motion`，关闭所有非必要位移。
- 不做滚动驱动装饰动画。

## Content Rules

- 产品文案使用“群、角色、场景、运行”等用户可理解词汇。
- `Harness`、`Director` 可作为模式名称，但必须有一句面向结果的说明。
- `idle`、`scheduled`、`passive_backoff` 等只出现在开发模式。
- 空状态说明当前缺少什么，并给出一个明确动作。
- 错误信息说明失败对象、原因和可执行的恢复方式。

## Required States

每个关键页面必须设计：

- Loading
- Empty
- Populated
- Saving / saved
- Unsaved
- Error
- Offline / reconnecting
- Permission or capability unavailable

聊天页额外包含 stopped、starting、running、paused 和 ended。

## Accessibility

- 所有命令使用原生 `button`、`a`、`input` 等语义元素。
- 颜色不单独表达状态，必须配合图标或文本。
- 所有图标按钮有可读名称和 tooltip。
- 焦点顺序与视觉顺序一致。
- 关系图必须提供等价的关系列表视图。
- 消息列表使用适合动态内容的 live region，但避免逐字朗读生成状态。
