# ChatVerse 产品文档

## 产品定位

ChatVerse 是一个可运行世界创作与智能体编排工具。

用户描述世界、角色、关系、开场和未解决的矛盾，World Architect 将想法整理成可编辑草稿。进入世界后，World Director 规划幕级剧情，Narrator 输出旁白与场景过渡，Actor 依据各自身份、认知和关系自主行动或说话。世界既可以普通叙事流运行，也可以切换为 Galgame 视觉小说式的舞台演出：旁白、角色、玩家逐棒接力，关键抉择交给玩家。玩家既可以亲自参与，也可以只观察世界运行。

ChatVerse 的核心对象是 World。群聊和私聊都是 World 中独立的沟通 Context，共享角色身份与世界背景，但不共享聊天记录，也不替代主世界叙事。

## 核心体验

### 创建世界

用户可以从一句设定、模板卡包或已有草稿开始，在同一个 Studio 中完成：

- 世界前提、基调和规则。
- 角色卡及角色自己的既有认知。
- 角色间的有向关系。
- 开场 Context。
- 初始剧情章节。
- 演出形式（Galgame 舞台或普通叙事流）。

内置模板卡包覆盖公版名著改编、现实协作、校园群像与科学史再创作：五行山、海棠诗社、赤壁议战、樱丘高校、夜班档案室、模拟法庭、索尔维会议。

创作助手与手动编辑器操作同一份 WorldDraft。Agent 提出的修改需要用户确认；手动修改、Agent 修改、校验、撤销、重做和预演使用同一套版本历史。

创作助手支持可选联网考据：用户要求基于真实历史、公版原著或现实设定创作时，助手可以联网核对事实并保留引用来源。联网只发生在创作阶段，世界运行时角色不会“上网”。

### 运行世界

三层智能体分工：

- World Director：规划幕级 Beat，维护剧情 Chapter / Beat / Edge 因果图，在场景需要时生成轻量临时角色，把当前情境交给合适的 Actor。不代写角色台词。
- Narrator：输出可观察的环境变化与场景过渡旁白，维持节奏，不重复已展示的内容。
- Actor：依据自己的认知判断是否回应，生成自然对话或有意义的动作，保持独立立场，不替其他角色作决定，也不读取完整导演世界书。

玩家可以发送消息、明确点名角色、请求继续观察或向 Director 提交宏观指令。

### Galgame 舞台演出

启用 Galgame 演出的世界以视觉小说方式呈现：

- 旁白、角色、玩家逐棒接力；每棒逐句确认（空格键推进），下一棒预取以减少等待。
- 到玩家回合时，系统根据玩家角色卡生成 2–4 个明显不同的合理选项与一个自动代演选项；也可以自由输入。玩家卡的身份、背景与权限是选项生成的硬边界。
- 按当前幕自动生成横向背景与角色立绘，支持多家图像服务，也可以上传自定义立绘。
- 开启自动代演后，玩家回合由提案自动提交，适合全程旁观。
- 演出状态随世界一起暂停、恢复、快照与冷恢复；停止不会留下失控的后台生成。

### 世界内通讯

用户可以在一个 World 内建立：

- 群聊：由独立 Harness 驱动，可运行、暂停，角色能够自主发言。
- 私聊：玩家与单个角色的问答式通讯，角色默认不会主动发送私聊。

这些 Context 使用同一角色卡和世界身份，但各自保存消息历史。主世界中的剧情记录不会被群聊或私聊消息替代。

## 作品与数据

浏览器本地作品库保存：

- World 草稿。
- World 运行存档。
- GroupCard 与关联资源。
- 独立角色卡。
- 演出视觉资产（Beat 背景与角色立绘）。
- 当前设备的模型连接配置与恢复指针。

作品默认存放在当前浏览器的 IndexedDB 中。群包和角色卡可以导出为文件并由用户自行交换；聊天历史、API Key、调试轨迹和运行时密钥不会写入分享包。

当前产品不提供云端社区、公开房间或在线模板发布。服务端的运行实例是临时的，浏览器本地作品才是用户数据的持久化来源。

## 模型连接

ChatVerse 使用用户自带模型连接配置。用户可以填写任意兼容 OpenAI Chat Completions 的服务地址、模型 ID 与 API Key。

- 文本模型：Director / 角色 / 创作助手可以分别指定模型；内置 DeepSeek 等预设。
- 联网考据模型（可选）：需要支持 Responses API 内置搜索的模型（如 deepseek-v4-flash）。
- 图像模型（可选）：支持多家图像生成服务，用于舞台背景与角色立绘。
- 本站不向用户售卖 Token。
- API Key 不写入 World、Group、角色卡、存档或调试事件。
- 用户主动运行世界或使用创作助手时，连接配置才会随请求发送到服务端。
- 不配置模型时，用户仍可浏览编排展示页和管理本地作品。

## 页面结构

- 首页：作品入口、运行中的世界、精选世界卡包。
- 世界库：本地 World 草稿与存档管理。
- World Studio：Agent 辅助与手动编辑结合的创作工作台。
- 世界运行页：叙事、角色输出、剧情图与玩家输入。
- Galgame 舞台页：逐棒演出、玩家提案、背景与立绘。
- 世界管理页：Context、角色状态、导演权限、剧情章节和运行设置。
- 剧情图：Chapter / Beat / Edge 的可视化浏览。
- 运行任务：暂停中的任务、待处理演出与后台整理。
- 角色库：可跨 World 使用的独立角色卡。
- 群包库：GroupCard 与 `.chatverse.zip` 的导入导出。
- Token 统计：按世界、角色与用途拆分的用量与缓存命中。
- 设置：模型与密钥、图像模型、本地存储、运行参数、演出参数与站点模式。
- Debug：运行时事件、调度、Prompt 与 Token 追踪。
- 展示模式：面向备案与技术说明的只读编排展示。

## 产品边界

当前版本包含：

- 单用户 World 创作与运行。
- Director、Narrator 与多 Actor 三层编排。
- 剧情 Chapter、Beat 和因果图。
- Galgame 舞台演出与玩家回合提案。
- World 内群聊与私聊 Context。
- 创作阶段可选联网考据。
- 舞台背景与立绘的图像生成。
- 本地作品库、导入导出和运行存档。
- 用户自带模型连接。
- 面向备案与技术说明的只读编排展示模式。

当前版本不包含：

- 账号、云同步和多人在线房间。
- 公开社区、作品广场和用户内容分发。
- 平台提供的模型额度。
- 付费、交易或订阅系统。
- 地点、物品、战斗数值等重型 RPG 系统。
- 自动导入长篇作品并构建完整世界的 Compiler。

## 质量标准

一个可发布的 World 应满足：

- 至少有一个有效 Actor、一个 Context 和一个可继续推进的剧情章节。
- 开场只描述可观察事实，不提前写死角色选择和剧情结果。
- Actor 不机械轮流、不重复旁白、不忽略玩家最近的有效发言。
- Director 每次运行产生明确推进，不用空旁白反复描述同一画面。
- Narrator 不补拍角色已提交的动作与决定，不把对话回放写成旁白。
- 舞台模式下逐棒确认不卡死，提案选项不突破玩家角色卡的边界。
- 群聊、私聊和主世界记录互相隔离。
- 暂停、停止、刷新和恢复不会留下失控的后台生成。
- Token 使用可追踪，Prompt 前缀稳定，历史与剧情上下文不会无限增长。

## 当前方向

ChatVerse 现阶段优先打磨个人世界创作与运行闭环：创建、校验、预演、启动、参与、保存和恢复，并继续完善 Galgame 舞台演出与模板卡包。社区、长期陪伴、多人协作与复杂 RPG 系统不进入当前开发范围。
